# Agent instructions

A product catalogue PoC meant to grow into a real product. Read `README.md` for what it does and `DECISIONS.md` for why.

## Layout

- `backend/`: Laravel 13 JSON API (PHP 8.5). Laravel-specific rules are in `backend/CLAUDE.md` (generated by Laravel Boost). Follow them.
- `frontend/`: React 19 + TypeScript SPA (Vite, React Router 7, Vitest).
- `compose.yaml`: local stack (api, queue, web, mailpit).

## Boundaries you must keep

These are the point of the design. Don't shortcut them.

1. **The frontend talks only to our API**, and only through `frontend/src/api/client.ts`. Never call Fake Store (or any product source) from the browser.
2. **The backend reads products only through `App\Catalogue\Contracts\ProductRepository`.** Code specific to a source (Fake Store quirks, HTTP, caching) stays in its adapter under `app/Catalogue/Sources/`. Controllers and services must not know which source is bound.
3. **The API shape is set by API resources** (`app/Http/Resources`), never by the source's payload. Changing it is a contract change, so update `frontend/src/api/types.ts` and the tests in the same change.
4. **Business decisions (e.g. featured products) live in our database**, not in the product source.
5. **Email goes through Laravel Mail** (queued mailables). No provider SDKs in application code; the provider is `MAIL_MAILER`.
6. **Styling uses the tokens in `frontend/src/styles/theme.css`.** No hard-coded colours or spacing in components.

## Commands

```sh
# Backend (from backend/)
php artisan test --compact        # run after every backend change
vendor/bin/pint --dirty           # format PHP before committing

# Frontend (from frontend/)
npm test                          # Vitest
npm run typecheck && npm run lint

# Whole stack
docker compose up --build
```

## Expectations

- Every acceptance criterion has tests on both sides: `backend/tests/Feature/*Test.php` and `frontend/src/**/*.test.tsx`. Keep them passing, and add tests with behaviour changes.
- Backend tests must never hit the network: `Http::preventStrayRequests()` is on, so use `fakeProductSource()`.
- Record new assumptions or cuts in `DECISIONS.md`.
- Never commit secrets or `.env` files; add new settings to the relevant `.env.example`.
